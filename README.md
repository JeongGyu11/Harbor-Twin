# HARBOR TWIN

한국해양진흥공사 해운·항만·물류 공모전 시연을 위한 가상 컨테이너선 하역·평형수 조정 웹입니다.

## 실행
VS Code에서 이 폴더를 열고 터미널에서 실행하세요.

    .\start.cmd

또는 Python으로 실행합니다.

    python -m http.server 4174 --bind 127.0.0.1 --directory dist

브라우저에서 http://localhost:4174 에 접속합니다. 수정 후 Ctrl+F5로 새로고침하세요.

## 사용 흐름
1. 3D 선박을 회전하거나 2D 도면에서 화물·탱크 상세를 확인합니다.
2. 하역을 시작하고 추천 운전안을 승인하거나 자동 균형 조정을 켭니다.
3. 하역 100% 후에도 마지막 물 이송이 남아 있으면 일시정지·재개할 수 있습니다.
4. 하역과 조정이 모두 끝나면 '다시 시뮬레이션'으로 새로 시작합니다. 수동 추천이 남으면 승인 후 재생해 마무리합니다.
5. 그래프와 최대 기울기 비교값에서 같은 하역 조건의 무조정 기준과 비교합니다.

## 튜토리얼
필수 기능 14개를 상세히 설명합니다. 실제 화면과 분리된 오른쪽 패널(넓은 화면) 또는 아래 패널(좁은 화면)을 사용합니다. 기능별 바로가기·다음·이전·건너뛰기를 지원합니다. 안내 중 재생이 멈추며 종료 시 원래 보기를 복원합니다. 개정된 가이드는 첫 방문에 다시 표시됩니다.

## 이번 수정
- 마지막 이송 중 일시정지가 초기화하던 문제 수정
- 물 이송 및 최종 상태까지 그래프 기록, 시간에 비례하는 가로축
- 가능한 탱크 조합 전체 비교, 승인 전 재검산, 수위 제한 확인
- 하중 변화로 방향이 부적절해진 이송 재평가
- 적재 높이·물의 높이에 따른 KG, 고정 KM 및 직사각형 탱크 자유표면 보정에 따른 추정 GM
- 계산 범위를 벗어나면 이송 중지, 0도 대신 계산 불가 표시
- 3D 수위와 2D 채움 비율 일치, 3D에서 고른 화물을 2D에서도 강조
- 포인터 취소와 작은 드래그 오인식 보완
- 새 완료 조건·그래프·계산 한계를 튜토리얼에 반영

## 검증
Node.js가 설치된 환경에서 아래 명령을 실행하면 상태·계산 회귀 테스트 17개를 실행합니다.

    node verify.mjs

테스트는 두 하역 시나리오의 완주, 물 총량 보존, 탱크 수위 범위, 마지막 이송의 일시정지·재개, 그래프 최신값, 탱크 대안 선택, 높이 및 수위에 따른 GM 변화, 계산 범위 초과 처리 등을 포함합니다.

## 모델 한계
현재는 물리 모델 기반 예측·탐색 및 현재 상태 규칙을 비교하는 시뮬레이션입니다. 학습형 AI는 미구현입니다. 실제 선형·운전 데이터가 없으므로 KM 고정, 선체 무게중심 및 탱크 형상 등은 가정입니다. 화물 높이를 반영한 초기 복원성 근사 모델이지, 실제 선박의 완전한 복원성·구조 강도 검증이 아닙니다. GZ 곡선, 실제 선형에 따른 KM 변화, 파랑·동적 거동, 센서·BWTS·실제 펌프/밸브 연동, 비용·체류 시간·전력 절감 검증은 포함하지 않습니다. '시연 기준 내'는 실제 선박 안전 판정이 아닙니다. 상세 가정은 화면 하단 '모델 및 계산 기준'에서 확인하세요.


## 공모전 검증용 보완 (2026-10-27)
- 현장 사용자·문제·업무 흐름 및 현재 구현/향후 AI 범위 표시
- 하역 간격, 유량, 시연 기준, 4개 초기 수위 설정과 72개 화물 CSV 입력 검증
- 60초 예측: 2초 간격으로 예정 하역과 이송을 계산하고 유지/이송 후보를 비교
- 후보 목적값: 예측 최대 절대 기울기 + 이송량 × 0.00003. 유지 대비 0.005° 이상 개선할 때 추천. 후보는 한 번에 한 쌍의 탱크 이송이며 전역 최적해를 보장하지 않음
- 예측 추천은 5초마다 재평가하고 승인 시 최신 조건으로 재계산. 승인된 예측 이송은 계획량을 수행한 뒤 재평가
- 별도 Worker에서 무조정/현재 상태 규칙/예측 탐색의 전체 하역 비교. 같은 화물·순서·수위·유량 사용, 자동 승인 비교이며 담당자 수동 운전 실적과 비교하지 않음
- 최대 기울기, 기준 초과 시간, 총이송량, 펌프 가동 초/시작 횟수, 수위 위반 및 완료 표시. 1초 간격 측정, 비용·전력·체류시간 절감으로 환산하지 않음
- 조건과 결과 JSON 내보내기, 화면 시뮬레이션의 운전 승인·재평가 로그

검증: `node verify.mjs` (기존 회귀 17개), `node verify-decision.mjs` (추가 검증 18개).
기본 한쪽 우선 하역 비교: 무조정 최대 5.97°, 규칙 0.35°, 예측 0.50°. 총이송량은 규칙 553.1 t, 예측 539.0 t. 예측이 모든 지표에서 우수하지 않으므로 결과를 그대로 비교한다.

## 제출용 정적 사이트
`dist/` 전체를 모듈 스크립트 및 Worker를 지원하는 정적 HTTP(S) 호스팅에 배포한다. 로그인이나 API 키는 필요하지 않다. 파일을 직접 더블클릭하는 file:// 실행은 지원하지 않는다.
`localhost`는 심사자에게 공유할 수 없으므로 별도 공개 URL이 필요하다. 현재 공개 배포는 수행하지 않았다. 접수 전에 심사자 환경에서 URL 접근과 Worker 실행을 확인하고, 접수 마감 후 배포 파일을 수정하지 않는다.


## 가상 파도 (2026-10-27)
- 입력 설정에서 끄기/잔잔함/보통을 선택하고 적용하면 초기화됩니다.
- 합성 파도 = 진폭 × [0.7 sin(2πt/8) + 0.3 sin(2πt/13)], 진폭 상한 0/0.25/0.75°. 고정 위상, 가상 시간 기반이며 일시정지·초기화 시 재현됩니다.
- 순간 기울기 = 하역·평형수 기울기 + 파도. 상단 부호(+우현/−좌현), 시계열 및 3D 자세에 반영합니다. 3D 자세는 기존과 같이 8배 확대됩니다.
- 추천에 전달되는 하역 성분은 합성 모델에서 직접 얻습니다. 실제 센서 신호를 필터링하거나 AI로 추정하지 않습니다. 따라서 파도 세기만 바꾸면 펌프 운전 결과는 같으며 이는 필터 성능의 입증이 아닙니다.
- 비교는 동일 위상·동일 하역 예정 시간 구간에서 순간 최대값과 기준 초과 시간을 평가합니다. 엔진의 하역/수위 상태는 1초, 파도는 0.25초 간격입니다. 이송·펌프 지표는 마지막 이송 완료까지 계산합니다. 화면 그래프는 실제 기록 시점 기준입니다.
- 실제 파고, 선형, 관성, 감쇠, 공진, 파면·선체 동역학은 계산하지 않습니다. 항만 운항 조건이나 선박 안전 판정 자료가 아닙니다.
- 튜토리얼 20단계 및 조건·결과 JSON에 파도 설명을 포함합니다.
- 추가 검증: `node verify-wave.mjs`.


## 3D 수면 연출
`ocean.js`는 GPU 정점 변위로 네 방향의 물결을 만들고 표면 법선, 광택·빛 반사, 파봉 포말을 표현합니다. 파도 끄기에서는 평평한 수면, 잔잔함/보통에서는 서로 다른 시각 진폭을 사용합니다. 가상 시간과 연동되어 일시정지·초기화를 따릅니다. 이는 시각 연출이며 기울기 계산의 합성 외란과 별개의 파형입니다. 실제 파고나 선체 유체역학을 계산하거나 선체와 물결을 물리적으로 결합하지 않습니다.


## 수면 추종과 물 품질 개선
GPU 수면과 CPU 선박 자세는 ocean-motion.mjs의 동일한 파형 상수를 사용한다. 선체 주변 15개 지점 평균으로 상하 움직임과 좌우·앞뒤 기울기를 계산한다. 시각 시간은 가상 시간의 0.22배로 재생하며 일시정지·초기화를 따른다. 하역 기울기는 8배 확대하고 수면 추종 기울기는 그대로 더한다. 이는 부력·관성·감쇠를 계산하는 유체역학이 아닌 기하학적 시각 연동이다. 그래프 순간 기울기의 합성 외란과는 별도 모델이다. 물은 절차적 하늘 환경 반사와 미세 표면 법선 및 절제된 파봉 포말을 사용하며 실제 선박 반사·굴절을 계산하지 않는다.


## 위치·시각·기상/해양 환경
환경 설정에서 부산/인천/울산 앞바다 또는 위경도를 고르고 한국시간 정각을 입력한다. Open-Meteo Forecast와 Marine API를 브라우저에서 병렬 조회한다. 예보 제공 범위 내 날짜만 가능하며 해양 결측·HTTP 오류·20초 타임아웃은 기존 적용 환경을 유지한다. 조회 후 적용 버튼이 필요하다. API 좌표는 해양 격자 때문에 요청 좌표와 다를 수 있다.
날씨, 풍속(m/s)/풍향, 유의파고(m)/파주기(s)/파향, 선수 방향을 직접 설정할 수 있다. 조회 원본, 요청 시각·좌표, 실제 API 격자 좌표, 수정 출처를 결과 JSON의 환경에 보존한다. 선택 시각 환경은 전체 실험 동안 고정하고 세 방식에 동일하게 적용한다. 환경은 새로고침 후 재적용이 필요하며 기존 파도 세기 저장과 구분한다.
수면 시각 진폭은 유의파고/2의 단순 매핑, 방향은 파향−선수 방향, 시간 배율은 8/파주기를 적용한다. 잔물결 법선에 풍속을 반영한다. 날씨·낮밤은 조명·안개·비/눈 입자에 반영하며 직접 설정의 낮밤은 한국시간 06–18시 근사다.
순간 외란(도)은 파고×0.35×[0.25+0.75|sin(파향−선수)|]의 2중 사인파 + 0.0008×풍속²×sin(풍향−선수)×sin(2πt/23)라는 가정이다. 실선박 응답계수·풍압 하중·RAO가 아니며 예보를 기반으로 실제 선박 안전을 예측한다고 주장할 수 없다. 하역 추천은 기존처럼 분리된 하역 성분만 사용한다. API 연결 자체는 학습형 AI가 아니다.
API: https://open-meteo.com/en/docs 및 https://open-meteo.com/en/docs/marine-weather-api (Open-Meteo · DWD 및 제공 기상기관 출처 표시). 튜토리얼 24단계. 검증: node verify-environment.mjs.


## 예보 자동 갱신
페이지 실행 중 기본 15분(선택 5/15/30분) 간격으로 현재 한국시간의 정각 또는 고정 선택 시각 예보를 다시 조회한다. 자동 결과는 별도 대기 데이터로 보관하여 기존 입력/적용 조건을 바꾸지 않는다. 새 예보 적용·초기화 버튼으로 적용한다. 실패 시 기존 조건을 유지하고 다음 주기에 재시도한다. 항구·모드 변경 중 도착한 오래된 응답은 무시한다. API 요청은 cache:no-store를 사용하지만 제공기관 모델 갱신보다 자주 조회해도 값이 달라지지 않을 수 있다. 페이지를 닫으면 멈추며 백그라운드에서는 브라우저에 의해 지연될 수 있다. 튜토리얼 25단계.


## 기상청 센서 관측
관측소 자동 매칭·관측시각·거리 표시 및 적용 경로를 추가했습니다. 인증키 미설정에서는 실제 수신·매칭 미검증입니다. 설정은 SENSOR_SETUP.md 참고. 센서 연결은 별도 로컬 중계 서버가 필요하며 정적 ZIP만으로 동작하지 않습니다.


## 서버 상시 수집
서버가 브라우저와 독립적으로 300초마다 기상청 부이자료를 수집해 SQLite에 저장합니다. 웹은 저장값만 읽습니다. 최근 30일 이력·최신값·항구별 수집 상태를 보존하고 실패 시 기존 자료를 유지합니다. 시작 시 첫 수집 이후 주기 실행하며 배포 서버의 지속 실행 및 DATA_DIR 영구 저장이 필요합니다. DEPLOYMENT.md와 Dockerfile/compose.yaml을 참고하세요. `python verify-collector.py` 7개 검증과 실제 7개 항구 첫 수집을 확인했습니다.


## 날씨 서버 수집 (추가)
서버는 Open-Meteo의 현재 시각 모델 예보를 7개 항구에 대해 5분마다 별도로 수집합니다. 추가 API 키는 필요하지 않습니다. 기존 기상청 센서 수집이 실패해도 날씨 수집은 독립 실행됩니다.
SQLite의 weather_latest/weather_history/weather_status에 최신값·최근 30일 이력·수집 상태를 보관합니다. 수집 실패 시 마지막 정상값을 유지하고 표시하며 수집 후 120분 또는 예보 기준 후 180분을 넘으면 적용을 막습니다.
`/api/weather?port=busan`은 저장 날씨만 조회하고 `/api/weather/status`는 항구별 수집 상태를 반환합니다. 웹은 처음 열릴 때 최신 저장 날씨를 표시하고 5분마다 화면을 갱신합니다.
날씨는 `sourceType=model_forecast`(Open-Meteo 모델 예보), 부이 바람·파도는 기상청 실제 관측으로 구분합니다. 날씨 적용은 날씨·낮밤만 변경하고 기존 센서 바람·파도를 유지합니다. 적용 출처와 서버 저장 날씨 원본은 결과 JSON의 weatherData에 포함됩니다.
기존 브라우저의 날짜·시간 지정 예보 조회는 별도 기능으로 유지합니다. 서버 저장 날씨는 현재 시각 자료이며 미래 선택 시각 자료로 잘못 표시하지 않습니다. 모델 예보를 센서 관측이라고 표시하지 않습니다.
서버 검증은 `python verify-collector.py` 9개입니다. 실제 7개 항구의 날씨·관측 첫 수집을 확인했습니다. 튜토리얼은 27단계입니다.


## 선택 시각 실제 관측 조회
항구와 한국시간 정각을 고르고 **실제 관측 조회 · 시뮬레이션 적용**을 누릅니다. `/api/observations/selected?port=busan&time=2026-10-27T16:00`은 기상청 원 API로 해당 시각 주변 실제 관측을 조회합니다. 정확히 일치하는 유효 관측을 우선하며 없으면 앞뒤 60분 중 가장 가까운 유효 관측, 동률이면 이전 관측을 선택합니다. 결측·범위 초과 값을 건너뛰고 미래 선택은 거절합니다. 날씨와 해양 관측은 각각 다른 시각일 수 있어 관측 시각·선택 대비 시간 차이·관측소 거리·원본 출처를 각각 보존합니다. 이 조회는 기존 최신값 5분 수집과 별개이며 기존 최신 DB 값을 덮어쓰지 않습니다.
해양은 승인된 kma_buoy.php의 시각별 자료를 사용합니다(요청 시각 직전 59분부터 요청 시각까지 응답하므로 세 구간을 조회한 뒤 ±60분으로 필터링). 날씨는 stn_inf.php inf=SFC에서 가까운 육상 ASOS를 매칭해 kma_sfctm3.php 시간자료를 조회합니다. ASOS는 항만 내부·부이와 동일 지점이 아닙니다. 관측소 거리 150km 한도를 적용합니다. 날씨 시각 분류는 현재일기 WC 또는 실제 강수량·운량을 사용하며 그 근거를 표시합니다. 모델 예보를 관측으로 사용하지 않습니다.
**실제 날씨 API 활용승인 완료: 2026-10-27 실제 ASOS·부이 통합 조회를 확인했습니다.** 기상청 API허브(https://apihub.kma.go.kr/) → 지상관측 → 종관기상관측(ASOS) → 시간자료 조회 `kma_sfctm3.php` 활용신청을 승인받아야 합니다. 기존 인증키를 그대로 사용하며 새 키가 필요하지 않습니다. 부이2 API의 추가 승인은 이 기능에 필요하지 않습니다. 승인 후 같은 화면에서 다시 조회하세요.
날씨·해양 모두 정상일 때만 자동 통합 적용합니다. 날씨 미승인·결측이면 기존 조건을 유지하고, 해양 자료만 있는 경우 별도 **해양 관측만 적용 · 날씨 유지** 버튼을 사용할 수 있습니다. 이 경우 날씨는 실제 관측으로 표시하지 않습니다. 선택 요청·원 관측·시간 차이는 환경 JSON의 selectedObservations에 남습니다. 튜토리얼에 사용법과 승인 안내를 추가했습니다.
검증: `python verify-collector.py` 14개(근접·동률·경계·결측·미래·두 출처 시각 차이·미승인 포함), `node verify-selected.mjs`(통합 적용, 차이 표시, 부분 자료 자동 적용 차단, 해양만 적용, 미래 차단), 기존 자동 갱신/환경 테스트 통과. 부산항 2026-10-27 16:00 실제 부이 조회·화면 적용 확인, 실제 ASOS 조회·부이 동시 조회를 확인했습니다.

2026-10-27 승인 후 확인: 부산항 16:00 요청 → 부산 ASOS159(10.05km)·이수도 부이22513(34.07km) 모두 16:00 실제 관측, 시간 차이 0분. 운량과 무강수·현재일기 생략 코드 IR/IX를 구분하고 결측을 무강수로 임의 대체하지 않습니다. 실제 관측 처리 테스트 15개 통과. 최신 모델 예보 저장 패널은 별도 출처로 유지합니다.


## 최신 실제 관측 자동 수집 (2026-10-27)
최신 날씨 패널은 이제 Open-Meteo 모델이 아니라 기상청 ASOS 실제 관측을 사용합니다. 기존 모델 조회 기능은 별도로 유지됩니다. 서버는 부이·모델 예보·ASOS 실제 날씨를 독립 스레드에서 각각 300초마다 수집합니다. ASOS 수집은 한 회차에 지점 목록 1회와 전국 최근 2시간 관측 1회 요청으로 수행합니다. 기상청 제공 지연으로 같은 관측 시각·값이 반복될 수 있습니다.
ASOS 실제 날씨는 DATA_DIR/weather-observed.sqlite3에 최신·30일 이력·수집 상태를 저장합니다. 기존 부이 DB 및 모델 저장과 분리되어 모델 값으로 실제 관측을 대체하지 않습니다. 실패 시 마지막 정상값과 오류를 유지합니다. 최신 ASOS는 150km 이내 관측소 중 최근 120분 내 유효한 날씨 분류가 있는 가장 가까운 지점을 사용합니다. 오래되거나 결측인 자료는 통합 적용을 막습니다. 이 120분 최신값 지연 한도는 과거 선택 시각 조회의 ±60분 규칙과 별개입니다.
/api/weather/observed/status: 실제 날씨 수집 상태 및 300초 주기.
/api/weather/observed?port=busan: SQLite 저장 실제 날씨.
/api/environment/latest?port=busan: ASOS 실제 날씨 + 부이 관측의 저장값만 조회(외부 API 추가 호출 없음).
웹은 최초 열기·항구 변경·5분 주기·다시 활성화 시 최신 저장 자료를 표시합니다. ‘최신 실제 날씨·해양 함께 적용’은 날씨·낮밤·풍속·풍향·파고·파향·주기를 반영하고 실험을 초기화하며 입력 필드도 갱신합니다. 기온은 정보 표시용이며 선체 물리 계산에는 사용하지 않습니다. 각 출처의 관측·수집 시각, 거리, 분류 근거를 보존합니다. 화면 갱신만으로 실험 조건을 덮어쓰지 않습니다. 기존 상시 서버·영속 DATA_DIR 구성이 필요하며 정적 호스팅만으로는 수집되지 않습니다. 튜토리얼에도 반영했습니다.


### 날씨 시각 효과 개선
3D 왼쪽 아래 ‘날씨 표현’은 기본 관측·설정 따라가기입니다. 풍향에 따른 빗줄기(최대2200개)·수면 파문, 부드러운 눈 입자(1300개)·바람과 난류, 다층 구름·관측 시정에 따른 안개 농도·날씨/낮밤 조명을 사용합니다. RN_INT가 유효하면 비 입자 수에 반영하고 결측은 기본 강도로 표시합니다. ASOS WC95–99는 관측 뇌우 효과와 연결됩니다. 태풍은 풍속만으로 실제 발생을 판정하지 않습니다.
비·눈·안개·뇌우·태풍 시연은 시각 효과만 변경하며 관측 원본과 물리 조건을 변경하지 않습니다. 번개 섬광은 기본 꺼짐이며 사용자가 켜고 재생할 때만 표시합니다. 일시정지 중 섬광은 꺼집니다. 실제 태풍 경보·강수·구름의 정밀 유체 모델은 아닙니다. 사용법은 튜토리얼에도 추가했습니다. `node verify-weather-fx.mjs`로 관측/시연 구분, 원본 불변, 시정·강수·코드 매핑을 검증합니다.
