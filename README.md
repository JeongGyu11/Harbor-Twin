# HARBOR TWIN

## 서비스 바로가기

### [웹에서 HARBOR TWIN 실행하기 →](https://harbor-twin-server.onrender.com/)

**시뮬레이션을 사용하려면 위 Render 주소로 접속하세요.** 프로그램 설치나 GitHub 저장소 다운로드 없이 브라우저에서 사용할 수 있습니다. 이 GitHub 저장소는 소스 코드와 개발 문서를 제공합니다.

> Render 무료 서비스가 휴면 중이면 첫 접속과 관측 수집에 시간이 걸릴 수 있습니다. 서버가 깨어난 뒤 화면의 관측 시각·수집 상태를 확인하세요.

HARBOR TWIN은 **화물의 위치·중량과 평형수 탱크 수량에 따른 선박 기울기 변화를 비교**하는 웹 시뮬레이션입니다. 한국해양진흥공사 해운·항만·물류 AX 공모전 시연을 위한 프로토타입으로, 인근 기상·해양 관측과 사용자 조건을 적용하고 물리 모델의 예측·추천을 LLM 업무 보조와 함께 살펴볼 수 있습니다.

## 처음 사용하는 순서

1. [공개 웹](https://harbor-twin-server.onrender.com/)에 접속해 **시작**하고, 처음이라면 **시작 가이드**를 확인합니다.
2. **환경 설정**에서 실제 관측 사용 또는 사용자 조건 실험을 선택합니다. 실제 관측은 항구·최신/과거 시각을 고른 뒤 **관측 조회·적용**을 누릅니다. 직접 설정은 입력 후 적용해야 실험에 반영됩니다.
3. **적재·탱크 실험**에서 화물과 탱크 수량을 비교하고 필요하면 **실험안 B를 메인 3D에 적용**합니다. 적용한 배치가 새 하역의 시작 상태가 됩니다.
4. **하역 설정**에서 순서·하역 간격·유량·조정 조건을 정하고 **시뮬레이션 시작**을 누릅니다. **운전 추천**에서 근거를 확인하고 승인하거나 자동 조정을 사용합니다.
5. **결과 비교**에서 동일 조건의 세 방식을 비교하고 기록을 저장합니다. 하역이 끝난 뒤에도 남은 평형수 이송이 완료됐는지 확인합니다.

메뉴를 다시 누르거나 닫기·Esc로 패널을 접을 수 있습니다. 패널 전환으로 입력값을 초기화하지 않습니다. **전체화면** 버튼 또는 F 키로 3D 화면을 확대할 수 있습니다. 핵심 5단계 가이드 외에 **상세 안내**, **AI 기능 가이드**를 제공합니다.

**초기화**는 메인에 적용한 실험안 B의 시작 배치를 복원합니다. 기본 예제로 돌아가는 동작과 구분됩니다. 메인 시간 진행은 현재 **하역**을 대상으로 하며, 적재 배치를 편집하는 기능이 화물을 순차적으로 싣는 동적 선적 시뮬레이션을 의미하지는 않습니다.

## 실제 데이터와 계산값은 어떻게 다른가요?

| 구분 | 출처와 의미 |
| --- | --- |
| 실제 날씨 | 기상청 ASOS 관측. 날씨 분류·기온·시정·강수 관련 값과 관측 시각·관측소 정보 표시 |
| 실제 해양 정보 | 기상청 해양기상부이 관측. 풍속·풍향·유의파고·파주기·파향 사용 |
| 모델 예보 | 고급 설정의 Open-Meteo 예보. 실제 센서 관측과 구분 표시 |
| 사용자 조건 | 직접 입력한 실험 값. 관측을 수정한 경우에도 실제 관측 원본과 구분 |
| 선박 계산값 | 가상 선박의 화물·탱크 배치로 계산한 기울기·추정 GM·추천 이송량 |
| 3D 연출 | 수면 추종·바람 물결·비·눈·안개·경고 등 시각화. 정밀 유체역학이나 실제 선박 거동 검증 결과가 아님 |

- 과거 시각은 유효 관측이 정확히 일치하면 우선 사용하고, 없으면 **앞뒤 60분 내 가장 가까운 값**을 사용합니다. 시간 차이가 같으면 이전 관측을 우선합니다. 실제 관측 시각과 요청 시각의 차이를 표시합니다.
- 미래 관측은 조회할 수 없습니다. 자료가 없거나 적용 범위를 벗어나면 통합 적용을 막고 기존 실험 조건을 유지합니다. 날씨와 해양의 관측 시각은 다를 수 있습니다.
- 비는 관측 강수강도 또는 관측 등급, 눈은 관측 등급에 따라 연출을 달리합니다. 강도 근거가 없으면 **기본 연출**이라고 표시합니다.
- 시정은 ASOS 원본 VS의 10m 단위를 km로 환산합니다. 기온 등 일부 값은 정보 표시용이며 선체 계산에 직접 사용하지 않습니다.

## 자동 수집과 데이터 보관

Python 서버는 **실행 중일 때** 웹 접속과 독립적으로 약 **5분마다** 실제 날씨·해양 관측을 수집해 SQLite에 저장합니다. 최신값·최근 30일 이력·수집 상태를 보관하고, 실패 시 마지막 정상값과 오류를 유지합니다. 5분마다 수집해도 제공기관 관측 시각이 갱신되지 않았다면 같은 값일 수 있습니다.

웹은 저장된 최신 자료를 읽고 표시를 갱신합니다. **표시 갱신과 실험 적용은 별개**이므로 수집 결과가 진행 중인 실험 조건을 자동으로 덮어쓰지 않습니다. 과거 날짜·시간 조회는 기상청 원 API를 조회하며 모든 과거 시각의 자료 제공을 보장하지 않습니다.

**Render 무료 서비스의 휴면·서버 중지 중에는 수집이 멈춥니다.** 영구 디스크 없는 파일 시스템의 SQLite 자료는 재시작·재배포 시 사라질 수 있습니다. 재가동 후에는 새 수집으로 최신값을 채웁니다. 끊김 없는 수집과 이력 보존은 상시 실행 서버와 영구 저장소가 필요합니다.

## AI의 역할

서버는 **Groq를 우선 사용하고 Gemini를 대체 공급자로 지원**합니다. 공급자 키는 서버에만 보관하며, 일반 웹 사용자는 키를 입력할 필요가 없습니다. 키 미설정·요청 한도·공급자 장애 시 AI 기능은 제한될 수 있습니다.

LLM은 개념·사용법·현재 상황을 설명하고, 가상 조건 질문에는 물리 모델 도구의 계산 결과를 바탕으로 답합니다. 채팅은 근거 있는 수치를 사용할 수 있으며, 확인되지 않은 수치나 안전을 단정하는 문장은 검증·조정합니다. 채팅만으로 실제 탱크 이송이나 화물 변경을 실행하지 않습니다. 적하목록 변환도 검토·적용 절차를 거칩니다.

**평형수 추천 수치를 계산하는 주체는 물리 모델과 후보 탐색이며 학습형 자율 제어 모델은 아닙니다.**

## 계산 범위

합성 기준 선체 12,000t, 화물 72칸, 평형수 탱크 4개를 사용하는 개념 검증입니다. 탱크 용량은 각 1,200t, 가정 운전 범위는 80–1,120t이며 적재·탱크 실험에서는 물리 용량 범위와 운전 범위를 구분합니다.

추정 GM은 고정 KM에서 화물·물의 높이에 따른 KG와 단순 자유표면 보정을 뺍니다. 하역·평형수 기울기와 합성 환경 외란을 구분하며, **3D 하역 기울기는 8배 확대**합니다. 수면 추종 자세와 수치 지표의 파형은 별도 시각·가정 모델입니다.

실제 선형에 따른 KM 변화, GZ 곡선, 구조 강도, 정밀 부력·관성·감쇠·공진, 실제 선박 센서·BWTS·펌프/밸브 제어는 구현 범위에 포함하지 않습니다. “기준 내”는 실제 안전 보장이 아니며 비용·전력·체류시간 절감 실적을 입증하지 않습니다. 상세 가정은 웹 하단 **모델 및 계산 기준**에서 확인할 수 있습니다.

## 개발자용 로컬 실행

서비스를 체험하려면 설치 없이 [공개 웹](https://harbor-twin-server.onrender.com/)을 사용하세요. 다음은 개발·자체 실행이 필요한 경우입니다.

```powershell
git clone https://github.com/JeongGyu11/Harbor-Twin.git
cd Harbor-Twin
Copy-Item .env.local.example .env.local
python observation_server.py
```

Python 3.12 기반 Docker 구성을 제공하며 Node.js는 검증 스크립트 실행에 사용합니다. 별도 프론트 빌드나 npm 설치 없이 `dist/` 파일을 제공합니다. `.env.local`에 키를 설정한 뒤 [로컬 웹](http://127.0.0.1:4175/)에 접속하세요. Windows에서는 `start.cmd`도 사용할 수 있습니다.

| 서버 설정 | 용도 |
| --- | --- |
| `KMA_API_KEY` | 기상청 실제 날씨·해양 관측 조회용. API별 활용 승인 필요 |
| `GROQ_API_KEY` | Groq AI 업무 보조 |
| `GEMINI_API_KEY` | 선택적 Gemini 대체 공급자 |

키가 없으면 실제 관측·AI 기능이 제한되지만 합성/직접 입력 실험은 사용할 수 있습니다. 실제 키·`.env.local`·관측 DB를 Git에 올리지 마세요. 개발상 프론트를 4174 포트로 따로 실행하는 경우에도 API 서버 4175가 필요합니다. 일반 실행에서는 **4175 하나로 웹과 API를 함께 사용**합니다.
